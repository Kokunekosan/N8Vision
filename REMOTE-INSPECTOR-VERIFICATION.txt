S5 remote inspector + fresh subject names

Apply over S4. Stop Vision, extract, restart and refresh BOTH desktop and remote
browser. No dependency installation. Existing paired credentials establish their
media session during browser startup; if your nonpersistent pairing expired when
the host restarted, pair again as normal. No live/GitHub changes.

Root cause: inspector img requests had no X-N8Vision-Credential header, unlike
JSON/thumbnail fetches. Remote network middleware returned 401. Added an explicitly
credential-authenticated media-session endpoint: same-origin HttpOnly SameSite=Strict
session cookie, Secure on HTTPS/reverse HTTPS. Middleware accepts that cookie only
for /api/file, /api/thumb and /api/grid-overlay; general API/admin actions still
require their existing header authorization. Revocation remains checked per request.
Credentials are never appended to source-image URLs. No anonymous asset bypass.

Inspector frame now fits known source dimensions (or provisional aspect ratio)
before image data arrives, with visible outline and Loading source image message.
Image readiness replaces provisional sizing; errors retain the frame and explain
that the source failed to load. Narrow/mobile layout reserves space for the stage.

Subject nouns no longer come from archived detections or manual labels. YOLAST
performs fresh identification under the >=65 naming gate, otherwise unidentified.
Archived masks can be reused only AFTER a fresh accepted name matches by label,
location and pixels. Reusing mask pixels does not inherit the old detector score.
Actual mask pixel ordering and separate human/object families remain: a large chair
annotation cannot seed a chair name or displace the sitting person. Original
manual/archive annotations are retained, rather than deleted or relabeled.
